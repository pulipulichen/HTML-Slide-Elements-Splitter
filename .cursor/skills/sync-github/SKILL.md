# 同步 GitHub

當使用者要求「同步 GitHub」或同義指示時，完成以下流程，不要只提供操作建議：

1. 檢查目前分支、工作樹、差異、未追蹤檔案、遠端及近期提交。先確認待提交內容屬於本專案；不得覆蓋或丟棄使用者變更。
2. 依專案 CHANGELOG 規則，將本次有意義的改動以英文摘要寫入所屬週期的 `changelog/CHANGELOG-YYYY.M.DD.md`，並在必要時更新根目錄 `CHANGELOG.md` 索引。依 Asia/Taipei 時區以週一作為週期起點；不得自行建立或提升語意化版本。保留現有內容與格式。
3. 檢查最終差異，避免納入憑證、機密或與本次同步無關的變更。若有無法判定是否應提交的重要檔案，先詢問使用者，不要猜測。
4. 以 Conventional Commits 格式建立清楚、精簡的提交訊息；本專案沒有對應 issue 時不需虛構 issue 編號。
5. 推送目前分支至 `origin`。推送前確認遠端狀態；若遠端有本地尚未包含的提交，先安全整合並再次檢查差異，不可使用 force push。
6. 確認提交及推送結果，回報變更摘要、提交雜湊與推送狀態。若任何步驟失敗，清楚說明目前完成到哪一步，不可宣稱已同步成功。

除非使用者另有指定，這個流程包含更新 CHANGELOG、commit 及 push；不得只更新其中一項便結束。
